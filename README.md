# グリーン・デイ ニュース

Green Day と、Blink-182・The Offspring・Rancid・Bad Religion・Weezer・My Chemical Romance など
周辺バンドのニュースを自動で集め、**日本語の見出し・要約・記事ごとの解説**を付けて公開する静的サイト。
収集元のほとんどは英語の音楽メディアなので、海外の記事も日本語で読める
（原文の全訳はせず、独自の解説＋Google翻訳へのリンク）。

- 公開先: GitHub Pages（`main` ブランチの `/docs`）
- 更新: GitHub Actions が6時間ごと（日本時間 3/9/15/21時）に実行
- 手動更新: `更新.command` をダブルクリック（ローカルで収集して push）

## 構成

| ファイル | 役割 |
| --- | --- |
| `feeds.json` | 収集元のRSS。`enabled: false` で一時的に外せる |
| `collect.py` | 収集 → 日本語化 → 解説生成 → `docs/` に書き出し |
| `llm_providers.py` | Gemini → Groq → Claude → OpenAI の順に試すフォールバック |
| `docs/index.html` | 一覧ページ（依存なしの1ファイル、PWA対応） |
| `docs/a.html` | 記事ごとの日本語解説ページ（`a.html?id=…`） |
| `docs/articles.json` | 掲載中の記事 |
| `docs/articles/<id>.json` | 記事ごとの解説 |
| `docs/skipped.json` | 一度見送った記事のID（同じ記事を何度もLLMに投げないため） |

## 見せ方

薄いグレーの背景に白いカードを置く、明るい配色ひとつだけ。
端末がダークモードでも同じ見え方にしている（`color-scheme: only light`）。

絞り込みは3段。

1. **すべて / 🎌 日本の話題 / 🌍 海外メディア / 🇯🇵 国内メディア**
   「日本の話題」は来日公演・日本のフェス出演・日本盤など、日本に関係するニュース。
2. **バンド** — 記事の主役。実際に記事があるバンドのチップだけ出る。
3. **カテゴリ** — 新曲・新作 / ライブ・ツアー / フェス出演 / メンバー・発言 /
   再結成・メンバー変更 / 再発・記念盤 / 映像・映画・書籍 / チャート・受賞 / その他

記事カードの下に出る小さなタグは、その記事に出てくるバンド名・人名。押すとその名前で絞り込む。

## 記事を載せるまでの流れ

1. **RSS取得** — バンドごとのGoogleニュース検索（英語15本・日本語5本）と、
   音楽メディア25本。どのフィードも、対象バンドの名前を含む記事だけ拾う。
   表記ゆれ（Blink-182 / blink 182 / ブリンク182）は空白・中黒・ハイフンを落として合わせる。
2. **ふるい（LLMに投げる前）** — Googleニュースの転送URLを元記事のURLに戻し、
   歌詞・セットリスト・チケット・写真ギャラリーのページ（`BLOCK_URL_RE`）、
   SNSと動画のドメイン（`BLOCK_DOMAINS`）、転載サイト（`BLOCK_SOURCES`）を落とす。
   さらに記事ページの `article:published_time` を読み、40日より古い記事を落とす。
   このときサムネイル（og:image）も一緒に取る。
3. **日本語化** — 5件ずつLLMへ。見出し・要約・バンド・カテゴリ・注目度を付ける。
   対象バンドの話題でないもの、「歴代ベスト〇曲」のような順位付けの記事はここで落とす。
4. **重複の除去** — 日本語の見出しどうしを比べ、同じ発表を伝える記事は1本にする。
   そのうえで、**同じバンド・同じ日の記事は3本まで**に絞る（`MAX_PER_BAND_DAY`）。
5. **解説の生成** — 原文の段落を取り出し、要点3〜5個＋800〜1200字の日本語解説を作る。
   英語の記事を先に処理する。本文が取れないページは2回試して諦める。

## 決めごと

- 原文の全訳はしない（翻訳権の侵害になるため）。載せるのは日本語の見出し・独自要約・
  独自解説・出典名・原文リンク。原文を読みたい人は詳細ページの
  「原文を日本語で全文読む」から Google 翻訳で読む。
- 歌詞と発言はそのまま引用しない。発言は要旨を日本語でまとめる。
- サムネイルは全記事に付ける。取れなかった記事はカテゴリごとの代替の絵（💿🎫🎪🎤…）で埋める。
- LLMが全滅したバッチは保存せずに捨てる（生煮えの記事を出さない）。RSSに残っているので
  次の実行で拾い直される。

## この題材ならではのハマりどころ

- **「Offspring」「Rancid」は普通の英単語**。Googleニュースの検索語は
  `"The Offspring" band` / `"Rancid" punk band` のように語を足す。ORは使わない。
- **Kerrang! のRSSは403**（ブラウザのUAでも通らない）。`site:kerrang.com` の
  Googleニュース検索で拾っている。**Punknews.org は本体ドメインではなく
  `static.punknews.org/feeds/punknews.rdf`**。
- **大きなライブが1本あると、各紙が別々の角度で書く**（開演前の告知・当日のレポ・
  共演者の話・メンバーの発言・写真ページ）。見出しの語がほとんど重ならないので
  機械的な重複判定では残ってしまう。最初の収集では My Chemical Romance の
  デトロイト公演だけで8件並んだ。日ごとに本数を決めて上から取るのが確実。
- **海外の発表を機械的に書き直して量産する配信サイトが混ざる**（Ad-hoc-news.de など）。
  初回は5件入り込み、そのうち1件は公演の年まで間違っていた。出典ごと落とす。
- **Googleニュースの転送URLのままだと、SNSの投稿や YouTube 動画が「記事」として並ぶ**。
  URLを元に戻してからドメインで落とす。
- **日本語の記事は数が少ない**。同じ日・同じバンドの本数を絞るとき、
  英語の焼き直しより先に日本語の記事を残すようにしている。

## 無料枠の蓋

`MAX_NEW_PER_RUN = 40`（うち Green Day 枠 `CORE_QUOTA = 16`）、`BATCH_SIZE = 5`、
`MAX_DETAILS_PER_RUN = 25`。溢れた分は次の実行（6時間後）に回る。

## 上のメニューの出し入れと、お気に入り（`docs/ui.js`）

`docs/ui.js` は**6つのニュースサイトで同じものを使っている共通ファイル**。

- **下にスクロールすると上のメニュー（見出し＋絞り込み）が隠れ、一番上に戻すと出る。**
  隠すのは見出しの高さを過ぎてから、戻すのは一番上に着いたときで、しきい値を分けて
  境目でちらつかないようにしている。
- **記事カードの右上の ☆ を押すとお気に入りに入り、「★ お気に入り」タブでまとめて読み返せる。**
  タブは絞り込みの1段目、「すべて」のすぐ隣に入る（末尾に足すと横スクロールの外に出て気づかれない）。
  詳細ページ（`a.html`）にも「☆ お気に入り」が出る。

ページ側に足してあるのは次の4つだけ。

| 場所 | 中身 |
| --- | --- |
| `<head>` | `<script src="ui.js" data-site="greenday-news"></script>`（**`defer` を付けない**） |
| `render()` | 記事カードを `<article data-id="${escapeHtml(item.id)}">` にする |
| `load()` | `all = window.NEWS_ITEMS = data.items || [];` |
| リンクの決め方 | `window.NEWS_LINK`（お気に入り一覧も同じリンク先を使うため） |

**気をつけること:**

- **`ui.js` は6サイトに同じ内容のコピーが置いてある。** 直すときは全部に配り直す。
  数え方は `md5 -q */docs/ui.js | sort -u | wc -l`（1なら揃っている）。
- **`data-site` を必ず入れる。** お気に入りは localStorage に持っていて、6サイトとも
  `mifune39428.github.io` の同じドメインにあるため、これが無いと互いのお気に入りが混ざる。
  URLから機械的に決めると、一覧（`/`）と詳細（`/a.html`）で別のキーになってしまう。
- **`<script>` に `defer` を付けない。** 付けると、詳細ページの `fetch` のほうが先に終わったときに
  `uiAttachDetail` がまだ無く、お気に入りボタンが付かないことがある。
  画面をいじる処理は `DOMContentLoaded` まで待つので、`<head>` に置いても表示は遅くならない。
- **お気に入りは記事のIDではなく記事そのものを写して持つ。** 一覧は30〜45日で入れ替わるので、
  IDだけ覚えても後から中身が引けない。入れ替わりで消えた記事は「掲載終了」と出し、
  解説ページではなく元記事へのリンクにする。

### 端末をまたぐお気に入りの引き継ぎ

お気に入りは各ブラウザの localStorage に入るので、そのままでは端末をまたげない。
静的サイトなので預け先も無い。**ふだんはQRコード1回で渡す**方式を主にしてある。

**QRコード／受け渡しリンク（既定。アカウントもトークンも要らない）**

- 「★ お気に入り」タブ →「ほかの端末へ渡す」でQRコードが出る。別の端末のカメラで読むと、
  そのままお気に入りが入る。リンクをコピーしてAirDropやメッセージで送ってもよい。
- お気に入りは**リンクの `#` より後ろ**に入れてある。この部分はサーバーへ送られないので、
  どこかに保存されることはない。
- **荷物を小さくするため、いま一覧に載っている記事はIDだけ渡す**（中身は受け取り側が
  自分の articles.json から引く）。一覧から落ちた記事だけ写しを同梱する。
  gzip（`CompressionStream`）で圧縮して base64url にする。
- **足し合わせなので、どちら向きに渡しても★は消えない。** 外した記事が復活しないよう、
  消した記録（`removed`）も一緒に渡す。
- QRは**型番20（97マス角）まで**。それを超える件数になると読み取れない大きさなので、
  リンクのコピーだけを案内する。だいたい40件くらいまでQRに収まる。
- 受け取り側は URL の `#fav=` を見て取り込む。**すでにサイトを開いている状態でリンクを踏むと
  ページは読み込み直されず `#` だけが変わるので、`hashchange` でも拾う**（これを忘れて
  一度動かなかった）。記事一覧が読めるまで待ってから取り込む（IDを引けないため）。

**QRコードは自前で作っている**（`ui.js` 内）。外部の部品を持ち込みたくないため。
バイトモード・誤り訂正レベルL・型番1〜40。**型番1〜40それぞれの容量ぎりぎりで
zxing に読ませて全件通ることを確認済み**（`segno` との行列比較は、パディングの流儀が
違うので使えない。「読めるかどうか」で検証すること）。

### 毎回自動でそろえたいとき（GitHub Gist・任意）

QRで渡すのが面倒なら、**GitHub の非公開Gist 1個**に預けて開くたびに自動で揃えることもできる。
設定画面の折りたたみの中に入れてあり、使わなくてもよい。

- 端末ごとに1回だけ、`gist` 権限のトークンを「★ お気に入り」タブ →「ほかの端末へ渡す」の中から貼る。
  トークンは**6サイト共通**（同じドメインなので分けても意味がない）。1回入れれば6サイトに効く。
- Gist は**説明文の目印 `newsfav-sync` で探す**。Gistのidを持ち歩かなくていいので、
  新しい端末はトークンを貼るだけで既存のGistを見つけられる。6サイトぶんを
  `favorites-<repo名>.json` という別ファイルで1つのGistに入れる（PATCHで自分のファイルだけ触る）。
- **消したことも覚えておく**（`removed` に消した時刻）。これが無いと、片方の端末で外した★が
  もう片方の端末の古い控えで復活する。付け直した時刻のほうが新しければ★は残る。
  墓標は180日で捨てる。
- 送る前に必ず読んでから混ぜる（read-modify-write）ので、2台で同時に触っても片方が消えない。
  取りに行くのは「開いたとき」「戻ってきたとき」「★を押した1.2秒後」。
- 圏外でも★の付け外しは手元で動き、つながったときにまとめて送られる。
- トークンを使いたくないときは、設定画面の「トークンを使わずに手で移す」から
  文字列をコピーして別の端末に貼る。

**トークンの置き場所について:** `mifune39428.github.io` に置いたページからはどれでも読める
localStorage に入る。`gist` 権限だけ・期限付きのトークンを使うこと。要らなくなったら
GitHub 側で失効させれば、その端末の登録も無効になる。

**「開き直すだけで揃う」を1台の設定だけで済ませる**

Gistの同期はトークンを貼った端末で有効になり、**そのあとは再読み込みのたびに自動で同期する**
（`init()` で `autoSync()` を呼ぶ。visibilitychange とは別経路なので、タブを閉じて開き直しても効く）。
面倒なのは「端末ごとにトークンを貼る」ところなので、**受け渡しリンク／QRに同期の設定も載せられる**
ようにした（QR下のチェックボックス。既定はオフ）。

- チェックを入れると、荷物に `t`（トークン）と `g`（Gistのid）が入る。
- 受け取った端末は、まだトークンを持っていなければそれを保存してすぐ同期する。
  以後その端末も「開き直すだけで揃う」状態になる。
- **トークンは `#` より後ろなのでサーバーには送られない**が、履歴とクリップボードには残る。
  だから既定はオフにしてある。QRを他人に見せると渡ってしまう点も注意。

**検証の落とし穴:** Claude_Browser のプレビュー面は `document.visibilityState` が常に `hidden` なので、
`visibilitychange` 経由の同期は動かない。読み込み時の同期が走ったかは
`performance.getEntriesByType("resource")` で `api.github.com` への通信を見て確かめる。
